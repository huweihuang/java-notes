Spring Boot注解

深入理解 Spring Boot 注解：使用方式与底层原理

1. 为什么 Spring Boot 中大量使用注解？

在学习 Spring Boot 时，你会发现代码里充满各种注解：

@RestController
@Service
@Autowired
@Configuration
@Bean

很多初学者会疑惑：

这些注解到底是什么？
为什么加一个注解功能就自动生效了？
Spring 是怎么识别这些注解的？

实际上：

Spring Boot 本质上是“基于注解驱动”的框架。

Spring Boot 的核心思想：

用注解代替 XML 配置

2. Java 注解本质是什么？

先理解 Java 原生注解。

示例

@Override
public String toString() {
    return "hello";
}

这里：

@Override

就是注解。

注解本质

Java 注解本质上是：

一种元数据（Metadata）

即：

给类、方法、字段增加额外信息

但注解本身：

不会自动执行逻辑

真正执行逻辑的是：

框架（Spring）

3. Spring Boot 注解的核心原理

Spring Boot 的核心流程：

启动Spring
    ↓
扫描类
    ↓
发现注解
    ↓
通过反射解析注解
    ↓
执行对应逻辑

本质：

反射 + IOC + 动态代理

这是 Spring 的三大核心。

4. Spring Boot 注解分类

Spring Boot 注解非常多，但核心可以分为：

分类 作用
Bean注解 注册对象
DI注解 依赖注入
Web注解 HTTP接口
配置注解 配置类
AOP注解 切面编程
条件注解 自动配置
生命周期注解 Bean生命周期

4.1. 最核心注解：@SpringBootApplication

示例

@SpringBootApplication
public class App {

    public static void main(String[] args) {
        SpringApplication.run(App.class, args);
    }

}

这是 Spring Boot 启动入口。

4.2. @SpringBootApplication 原理

它实际上是：

@SpringBootConfiguration
@EnableAutoConfiguration
@ComponentScan

三个注解组合。

4.3. @ComponentScan 原理

作用：

扫描 Spring Bean

例如：

@Service
public class UserService {

}

Spring 启动时：

扫描包路径
发现@Service
创建对象
放入IOC容器

IOC 容器是什么？

IOC：

Inversion of Control（控制反转）

以前：

UserService s = new UserService();

自己创建对象。

现在：

对象由Spring管理

你只需要：

@Autowired
private UserService userService;

Spring 自动注入。

4.4. @Component 系列注解

4.4.1. @Component

最基础 Bean 注解。

@Component
public class OrderManager {

}

Spring 会创建对象。

4.4.2. @Service

业务层。

@Service
public class UserService {

}

本质：

@Component

只是语义更清晰。

4.4.3. @Repository

数据库层。

@Repository
public class UserDao {

}

特点：

自动转换数据库异常

4.4.4. @Controller

MVC 控制器。

@Controller
public class UserController {

}

用于返回页面。

4.5. @RestController

REST 接口。

@RestController
public class UserController {

}

等价于：

@Controller + @ResponseBody

返回 JSON。

4.6. @Autowired 原理

使用

@Service
public class UserService {

}

注入：

@RestController
public class UserController {

    @Autowired
    private UserService userService;

}

4.7. @Autowired 底层流程

Spring 启动：

扫描Bean
    ↓
创建Bean
    ↓
放入IOC容器

@Autowired 时：

根据类型查找Bean
    ↓
找到 UserService
    ↓
通过反射赋值

类似：

field.set(object, bean);

5. IOC 容器底层结构

本质：

Map<String,Object>

类似：

Map<String, Object> ioc = new HashMap<>();

Spring 内部：

ioc.put("userService", new UserService());

@Autowired：

ioc.get("userService");

6. Bean 生命周期

Spring Bean 生命周期：

扫描Bean
    ↓
实例化
    ↓
依赖注入
    ↓
初始化
    ↓
使用
    ↓
销毁

6.1. @Bean 注解

除了类注解：

@Service

还可以：

@Bean

示例

@Configuration
public class AppConfig {

    @Bean
    public UserService userService() {
        return new UserService();
    }

}

6.2. @Bean 原理

Spring 启动：

扫描@Configuration
    ↓
扫描@Bean方法
    ↓
执行方法
    ↓
返回对象加入IOC

等价：

ioc.put("userService", userService());

7. @Configuration 原理

示例

@Configuration
public class Config {

}

作用：

声明配置类

为什么特殊？

Spring 会：

使用 CGLIB 动态代理增强@Configuration

7.1. 为什么要增强？

例如：

@Configuration
public class AppConfig {

    @Bean
    public A a() {
        return new A();
    }

    @Bean
    public B b() {
        return new B(a());
    }

}

如果不增强：

a() 会执行两次

会创建两个对象。

Spring 用 CGLIB 保证：

@Bean 永远单例

8. Web 注解详解

8.1. @RequestMapping

最基础路由注解。

@RequestMapping("/user")

8.2. @GetMapping

GET 请求。

@GetMapping("/list")

8.3. @PostMapping

POST 请求。

@PostMapping("/save")

9. 参数接收注解

9.1. @RequestParam

接收 URL 参数。

@GetMapping("/hello")
public String hello(@RequestParam String name) {
    return name;
}

请求：

/hello?name=tom

9.2. @PathVariable

路径参数。

@GetMapping("/user/{id}")
public String user(@PathVariable Long id) {
    return "id=" + id;
}

请求：

/user/100

9.3. @RequestBody

接收 JSON。

@PostMapping("/save")
public String save(@RequestBody User user) {
    return user.getName();
}

10. @RequestBody 原理

Spring MVC：

HTTP请求
    ↓
DispatcherServlet
    ↓
HandlerAdapter
    ↓
HttpMessageConverter
    ↓
Jackson JSON解析

最终：

JSON → Java对象

11. @Value 注解

读取配置。

server:
  port: 8080

读取：

@Value("${server.port}")
private String port;

12. @ConfigurationProperties

批量读取配置。

配置

user:
  name: tom
  age: 18

类

@Component
@ConfigurationProperties(prefix = "user")
public class UserProperties {

    private String name;

    private Integer age;

}

13. AOP 注解

AOP：

面向切面编程

用于：

  • 日志

  • 监控

  • 权限

  • 事务

14. @Transactional 原理

示例

@Transactional
public void save() {

}

底层

Spring：

使用动态代理

执行：

开启事务
    ↓
执行方法
    ↓
提交事务

异常：

回滚事务

15. Spring AOP 本质

Spring 不会修改原代码。

而是：

生成代理对象

例如：

UserService
    ↓
ProxyUserService

调用：

proxy.save()

实际上：

事务逻辑
    ↓
原始save()

16. 动态代理

Spring 两种代理：

类型 技术
JDK动态代理 基于接口
CGLIB 基于继承

17. 自动配置原理

Spring Boot 最强大的能力：

自动配置

17.1. @EnableAutoConfiguration

核心注解。

17.2. 启动流程

读取 spring.factories（旧版本）
或
AutoConfiguration.imports（新版本）
    ↓
加载自动配置类
    ↓
按条件生效

18. 条件注解

例如：

@ConditionalOnClass

意思：

如果某个类存在
才启用配置

示例

@ConditionalOnClass(DataSource.class)

如果项目存在数据库依赖：

自动配置数据库

19. 注解原理

19.1. 为什么引入依赖就能自动工作？

例如：

spring-boot-starter-web

Spring Boot 自动：

  • Tomcat

  • MVC

  • JSON

  • DispatcherServlet

因为：

自动配置类生效了

19.2. Spring Boot 注解底层技术总结

Spring Boot 底层核心：

技术 作用
反射 解析注解
IOC 管理对象
动态代理 AOP
CGLIB 增强配置类
ClassLoader 加载类
ASM 解析字节码

19.3. Spring 启动流程（非常重要）

19.3.1. 启动：

SpringApplication.run()

19.3.2. 内部流程

创建Spring容器
    ↓
扫描类
    ↓
解析注解
    ↓
创建BeanDefinition
    ↓
实例化Bean
    ↓
依赖注入
    ↓
AOP代理
    ↓
启动Tomcat

19.4. BeanDefinition 是什么？

Spring 不会直接创建对象。

先创建：

BeanDefinition

类似：

对象的说明书

记录：

  • 类名

  • 作用域

  • 是否单例

  • 构造方法

  • 依赖关系

19.5. Spring Boot 为什么这么强？

因为：

Spring = 工厂
Spring Boot = 自动化工厂

开发者：

只需要声明

Spring：

自动完成大量工作

真正学会 Spring 注解：

不要只会“用”

- IOC
- 反射

- Bean生命周期

否则：

只能停留在CRUD阶段

22. 总结

Spring Boot 注解本质：

注解 = 元数据
Spring = 注解解析器

Spring Boot 通过：

  • 反射

  • IOC

  • 动态代理

  • 自动配置

实现：

“声明式编程”

开发者：

只需要写：
@Service
@RestController
@Transactional

Spring 自动完成：

  • 创建对象

  • 注入依赖

  • 创建代理

  • 开启事务

  • 注册接口

  • JSON转换

这也是 Spring Boot 能成为 Java 企业开发核心框架的根本原因。
